DETAILED ERROR AND FIX LOG
--------------------------

FIX-001: Flat navigation did not communicate the required research workflow
Date: 2026-08-18
Type: Architecture and usability
Status: Fixed

Observed problem:
The earlier application behaved like a collection of equally weighted pages.
It did not clearly show the required order of dataset preparation, settings,
evaluation, result review, and export.

Fix:
- Introduced modern Streamlit multipage routing.
- Added a visible workflow stepper and shared Previous/Next navigation.
- Added central routes, progress selectors, and prerequisite guards.
- Separated Compare Algorithms from Generate & Listen.
- Locked generation until evaluation is genuinely complete.

Research-integrity result:
The interface now reflects the required Leave-One-Recording-Out comparison flow
and does not imply that generation is available before a valid comparison exists.


FIX-002: Generation and sound-preview stages needed real application behavior
Date: 2026-08-18
Type: Missing workflow capability
Status: Fixed

Observed problem:
The generation and audio portions needed to operate as real research stages rather
than decorative or planned screens.

Fix:
- Added final-model training on all verified recording groups after evaluation.
- Added bounded 16-, 32-, and 64-event token generation.
- Added deterministic sampling controls and explicit starting-context handling.
- Added sample-bank validation and dataset-derived timing for sound previews.
- Added WAV output and token-to-sample mapping logs.

Research-integrity result:
The algorithms continue to train on event-token sequences, not WAV files. Audio
is described as a sound preview/sample-rendered research simulation, not an
authentic reconstruction of a traditional performance.

FIX-009: Algorithm comparison failed during dataset configuration
Date: 2026-08-22
Type: Runtime defect
Status: Fixed

Captured application report:
- Heading: Training Completed with Warnings or Errors
- Result: 0 of 15 runs finished successfully.
- Algorithm: All
- Fold: None
- Test group: None
- Stage: configuration
- Error: "A PreparedSequenceDataset or recording-sequence mapping is required."
- Error type: DatasetPreparationError

Root cause:
Streamlit can reload an imported module while preserving an older prepared dataset
object in session state. The old object still contained valid encoded recording
sequences, but a strict isinstance check compared it with the newly loaded class
identity and rejected it.

Fix:
The evaluation orchestrator now passes the prepared object's encoded recording-
sequence mapping into the Leave-One-Recording-Out fold builder. The fold builder's
existing mapping contract remains valid across a Streamlit hot reload.

Files involved:
- thesis_system/src/services/model_training.py
- thesis_system/tests/test_model_training.py

Regression protection:
Added a test that simulates a stale prepared-dataset object from before a module
reload and confirms that evaluation can still build folds from its valid mapping.


FIX-010: Training failures were visible but not conveniently downloadable
Date: 2026-08-22
Type: Error reporting
Status: Fixed

Observed problem:
The training report displayed errors in the popup, but the user needed a portable
record for troubleshooting and thesis documentation.

Fix:
- Added a downloadable training_error_report.csv to the warning/error dialog.
- Added the same error-report download to the Train & Test page.
- Kept algorithm, fold, test group, stage, error, and error type in the report.

Result-handling rule:
- Genuine partial results remain viewable and exportable when at least one run
  succeeds.
- Failed folds are never replaced with fabricated metrics.
- Zero genuine results do not unlock the next research stage.
- Generate & Listen remains locked until the selected comparison is complete.
